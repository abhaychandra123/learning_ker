## Summary

1. **The data-consistency correction works, with μ chosen on simulation only and without being told the
   standoff.** One Tikhonov step after MAGIC-UNet run 2, at the height h* read from its own predicted current, lowers
   the 15-pair COMSOL error at 3 → 0.5 µm from **27.0% to 24.3%** (C1 family 26.3 → 23.8%, IC_4um 29.6 → 26.4%).
   Given the true height instead, it scores the same 24.3%. It works by fixing the measured band (in-band error
   16.0 → 11.0%; FISTA-1000: 9.1%) and leaves the prior band unchanged (14.6%). It also lowers the simulated error at
   every standoff for both runs. Decision rule (a) passes. Like for like, on the review's two configurations, μ chosen
   on simulation gives 25.1%, so the review's 24.2% (three μ values tried on the test data) was about 0.9 points
   optimistic.
2. **The fair classical baseline is FISTA-1000, not FISTA-300, and it draws level with raw MAGIC-UNet.** By amendment A2
   (lowest 64-crop validation score, fixed before any COMSOL number at 1,000 or 3,000 iterations was read) the
   reference depth is 1,000 iterations: 34.0% on validation, against 35.5% at 300 and 36.3% at 3,000. On COMSOL it
   scores **26.7%** (C1 family 26.6%, IC_4um 27.2%), against FISTA-300's 30.5%. **Raw MAGIC-UNet run 2 (27.0%) no
   longer beats it; only the corrected run 2 does:** 24.3 against 26.7% overall, C1 family 23.8 against 26.6%, IC_4um
   26.4 against 27.2%. The IC margin is 0.8 points on three component images. By amendment A4 (written before any
   seed result) a margin counts only if all three corrected seeds score below FISTA-1000 on that shape; the seeds are
   still running.
3. **The global height read-out works on the C1 shape and fails on the IC coil.** On simulation, run 3 (trained
   1–10 µm) reads the standoff within 15% for 93% of images at 1.5–8 µm (median error 4–9%, a +5% bias), and the
   estimated-height correction costs 1.2–4.1 points against the true-height one. On COMSOL, C1 shapes read 2.97–3.10
   µm at 3 µm. On IC_4um, run 3 reads 3.86 µm at 3 µm and is too high by 0.7–1.8 µm at 3–6 µm, so the estimated-height
   correction only lowers its error from 52.0 to 46.9% (true height: 37.3%). Decision rule (b) passes on simulation
   in the middle of the range and fails on the IC coil. **The review predicted that one global height would rescue run
   3 on the IC coil; that prediction was wrong.** The network's current itself is biased there, and a height read from
   a biased current inherits the bias.
4. **The measuring stick, repaired.** Above the noise cutoff k_n = 2.9 rad/µm (fixed from the targets alone), every
   method's error equals the target's own content there (15.6–16.2% of the target norm, against the target's share of
   15.7%). No method can change that term. The band errors add in quadrature, so it lifts a raw score by about 4–6
   points, not 15.7 (24.3% → about 18.4% and 30.5% → about 26.2% with it removed); it is 26–43% of the squared error.
   All band numbers in this file are norm fractions ‖·‖/‖T‖, not energy fractions. The ranking against the low-passed target is the same as
   the raw ranking, but the gaps between methods widen slightly (run 2 corrected 18.5%, FISTA-1000 21.9%, run 2 raw
   22.0%, FISTA-300 26.4%).
5. **Every saved Group B model was re-run with its own frozen code and reproduced its saved COMSOL scores exactly**
   (difference 0.0 on all 8 models × 15 rows). MAGIC-UNet inference reproduced to 1.5e-14.

## M2a. Noise cutoff from the targets alone

`runs/m1_m2/cutoff/` (`cutoff.json`, `profile.csv`). The pooled inconsistent share of the five 0.5 µm targets stays
below 3% from 0.3 to 1.7 rad/µm, rises through 14–31% at 1.9–2.4 rad/µm, and first exceeds 0.5 in the bin at
**2.9 rad/µm**. Per target the same rule gives 2.7 (IC_4um) and 2.9 (the four C1 configurations). Above about 3
rad/µm the share stays at 0.42–0.61 out to 12 rad/µm. Pure component-independent noise would give about 2/3, so that
band is mostly noise. The share is 13.5% in the lowest bin (0–0.1 rad/µm), as expected from truncation at the image
edge; that is why the rule starts at 1 rad/µm.

In my review I used 2.2 rad/µm as the noise edge. That value was chosen by eye; the rule fixed in advance gives 2.9.
Between 2.2 and 2.9 rad/µm the targets are only 25–49% inconsistent, so part of that band is real signal.

The SNR = 1 crossings at 3 → 0.5 µm reproduce `information_budget.py`: L1_C1 1.05/1.15/1.60 rad/µm, IC_4um
1.15/1.15/1.15, data3 configurations 1.00/1.15/1.20.

### Decision rules (protocol §M1)

| Rule | Criterion | Result |
|---|---|---|
| (a) | Correction at true height lowers simulated error at 3 µm, then COMSOL error | **Pass.** Simulation 15.1 → 12.7% (run 2); COMSOL 27.0 → 24.3% |
| (a) failure signature | Helps COMSOL but hurts simulation | Not seen: at the true height it helps all 24 simulated run-standoff cells and all 40 COMSOL rows |
| (b) | Run 3 \|h*−h\| ≤ 15% of h on simulation over 1–10 µm | **Partial.** Per median: met at every standoff except 1 µm (18%) and 10 µm (22%). Per image: 84% over 1–10 µm, 93% over 1.5–8 µm. The protocol did not say which; both are reported |
| (b) | Run 3's IC_4um error falls clearly with the estimated-height correction | **Fail as a rescue.** 52.0 → 46.9%, against 37.3% at the true height and 29.6% for raw run 2 |
| (b) failure signature | Run 2 h* sticks near 3 µm for 2 and 4 µm | Not on simulation (2.05, 4.01); mildly on COMSOL (2.32; 3.61/3.34) |
| (b) failure signature | Run 3 h* sticks to the top of its range on the IC coil | Not at the top (3.9–6.8 µm), but biased high by 0.7–1.8 µm at 3–6 µm |

**What M1 means for the method.** Data consistency is worth keeping: it is free, it was chosen on simulation, and it
helps everywhere. A height read off a feed-forward network's current is only as good as that current. Where the
network is wrong (run 3 on closely spaced wire pairs), the read-out is wrong in the same direction. So M5's height
search has to re-run the reconstruction at each candidate height, not re-project one prediction. That matches the
design in `FABLE_REVIEW.md` §4.1 (resample to the hypothesised standoff, reconstruct, then score). This shortcut was
the cheapest possible test of joint estimation, and it says the cheap shortcut is not enough.

What the four-way split shows:

- **The noise band is a term every method shares.** Every field-domain method outputs nothing there (error = target
  share, 15.6%), and MAGIC-UNet outputs a little that does not match (15.9%). It enters the raw score in quadrature, so
  it compresses the differences between methods rather than adding a fixed number of points. Roughly (the quadrature
  rule holds per component, not exactly for means), √(30.5² − 15.6²) ≈ 26.2% is FISTA-300's error with the noise band
  removed, and √(24.3² − 15.9²) ≈ 18.4% is corrected run 2's.
- **Field-domain methods differ almost only in the prior band** (19.3–31.2%, against a target share of 32.9%):
  FISTA-1000 recovers the most of it among them. Their in-band errors are 9.0–16.4%.
- **Running FISTA from 300 to 1,000 iterations gains in the prior band, not in-band** (23.8 → 19.3%; in-band 9.6 →
  9.1%). From 1,000 to 3,000 it loses in the prior band again (20.2%) while in-band barely moves (9.0%), which is
  consistent with the extra iterations fitting noise above k_c.
- **MAGIC-UNet's advantage is entirely in the prior band** (14.6% against FISTA-1000's 19.3%, a 4.7-point lead; the
  lead against FISTA-300 was 9.2 points). Its raw in-band error is the worst of the good methods (16.0%); the
  correction brings it to 11.0%, still 1.9 points behind FISTA-1000's 9.1%. A correction on top of FISTA is not in the
  protocol and was not run.
- **The IC coil changes rankings among the uncorrected methods**: on the low-passed IC target FISTA-1000 (21.2%) and
  FISTA-300 (21.8%) beat raw run 2 (23.9%); only corrected run 2 is lower (19.8%). It is one shape with three
